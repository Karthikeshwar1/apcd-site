🎯 TL;DR

Same app, same model (Sonnet 5.5, low effort), same quality: every run passed 30/30 API tests and 20/20 UI checks.

Comparison Tokens Used Speed Runs Sampled
Desktop app: Claude projects coordinator vs APCD Projects used 1.6× more – 2 vs 1
CLI: Claude Code + sub-agents vs APCD Sub-agents used 1.1–1.3× more (1.15× on cost) APCD 2× faster 2 vs 3
Why

An orchestrator adds a “manager” agent that re-reads its whole growing conversation on every step, and its sub-agents re-explore the code. APCD has no manager. One short project doc lets each fresh chat pick up exactly where the last one stopped.

“In my experience, orchestrator coordination hasn’t been great yet. It’s like manual shift vs auto transmission, back when auto transmissions were just introduced.” — Karthik, 2026-10-12

1. What We Compare

Arm How work is split How context carries over
P: APCD plugin The human opens one new chat per milestone (6 chats) CLAUDE.md Progress list
O: orchestrator A coordinator spawns one sub-agent per milestone (1 + 6) The coordinator’s handoff notes
  • O flavours: the desktop Claude projects coordinator, and a CLI session + sub-agents (claude -p).
  • Compare only on the same surface: Desktop vs CLI changes cost a lot by itself (§4).
  • Scope: Token efficiency only. Coordination quality isn’t scored.
  • Excluded: A single solo chat. Real big projects need a split.

2. Setup

  • Specimen: Linkshelf (SPEC.md). A bookmark API plus a one-page UI, Node with zero dependencies, ~400 LOC, 6 milestones.
  • Model: Sonnet 5.5, effort low, everywhere.
  • Environment: The same plugins and MCP in all runs (realistic, not stripped).
  • APCD version: Published, without the auto-refresh hook.

Metrics

Metric What it is
Input units (main) in×1 + 5-min cache write×1.25 + 1-hour cache write×2 + cache read×0.1, which is Anthropic’s relative pricing.

  • Runs are stable: APCD varied ±4% across 3 runs, O varied ±1% across 2.
  • APCD’s biggest cost is its cache price: Each new chat writes the 1-hour cache at 2× base price; sub-agents write the 5-minute cache at 1.25×. That is about 2/3 of APCD’s input units.

5. Findings

1

APCD never cost more at equal quality

It was 1.6× cheaper than desktop projects, and 1.15× cheaper in $ and 2× faster than CLI sub-agents.

2

The manager agent is the tax

Its context grows every step, and it waits between sub-agents, which slows things down.

3

Surface matters as much as method

The desktop app made orchestration about 2.3× pricier than the CLI.

4

Orchestrators don't always orchestrate

“Use sub-agents as you see fit” produced zero sub-agents, so the O prompt forces them.

5

Quality is equal on every automated check

The visual comparison is still pending blind rating (round 1’s APCD UI looked plainer).

6. Caveats

  • It’s a small, focused specimen (about 400 LOC). Big, messy projects may differ.
  • The desktop comparison is n=1 for APCD vs n=2 for projects.
  • APCD trades a little laziness: you open each new chat yourself, while orchestrators do it for you.
  • It was a single model and effort level (Sonnet 5.5, low).

7. How to Run More

cd S:/PROJECTS/dir2_learner/apcd-benchmark/apcd
node tools/bench.mjs run P <new-name>
node tools/bench.mjs run O <new-name>
node tools/bench.mjs score <folder-name>
node tools/bench.mjs blind r2
  • run: CLI, auto-scored.
  • score: for a manual desktop run in S:/bench/<folder-name>.
  • blind: blind visual rating page.
  • Use a new name per run. Folders are never reused.
